# Methodology

Every test times After Effects or Cinema 4D doing a fixed job on identical,
generated assets. The full plan, including the scoring model, is in the
Phase 1 architecture document.

## Assets

- **After Effects project:** generated on each machine by `scripts/ae/build_project.jsx`
  (newer `.aep` files do not open in older versions, and the studio runs 2025 and later).
  16 bits per channel, 3840×2160, 25 fps. Only built-in effects. Text uses Arial, present on Mac and Windows.
- **Cinema 4D scenes:** generated by `scripts/c4d/build_scenes.py` inside c4dpy.
- **Footage:** `assets/footage/`, made with `tools/make_footage.sh`. A 4K H.264 clip at about
  45 Mbit/s, a 4K ProRes 422 Proxy clip and two 4K stills. Checked against `SHA256SUMS` before every build.
- Anything the build could not create in a given version (a missing effect or parameter) is listed
  in the result under `builds.*.missing`, and `workload_complete` is false. Such results must not be
  compared directly with complete ones.

Start-up of After Effects and Cinema 4D is excluded from render and evaluation times.
aerender has no "render only" timer, so the runner timestamps its output lines: it
uses the time between "Starting composition" and "Finished composition", or, when
those English lines are missing, the per-frame progress lines. If neither is
available it falls back to wall time and records `timing_method: wall_time`.

Every aerender call uses `-mem_usage 50 90` and an explicit `-mfr` setting, so personal
memory and MFR preferences do not change the result.

## Protocol

1. **Preflight:** AC power, at least 20 GB free (warning under 60 GB), up to 10 minutes
   waiting for CPU use under 15%, busiest processes recorded.
2. **Cool-down** before each test: at least 30 s (10 s in quick mode) and until the thermal state is nominal or fair.
3. **Warm-up** run, recorded but not scored (not for After Effects renders, see 4).
4. **Measured runs:** 5 (quick: 3). After Effects renders: 3, with fewer frames in quick mode; the AE disk cache is emptied before every render, so each run renders from scratch instead of reading the previous run's cached frames. Multitasking: 3 (quick: 1).
5. **Statistics:** median. With 5 or more runs, a run more than 3 scaled MADs from the
   median, and more than 2% away from it, is an outlier: kept in the raw data, excluded from the median. A test is
   `invalid` if fewer than 3 good runs remain or the coefficient of variation exceeds 10%.
6. **Monitoring** every 2 s: thermal state (macOS), CPU speed limit (Intel Macs), memory
   free, swap, compressed memory (macOS), CPU use (Windows), GPU temperature and thermal
   throttling (NVIDIA on Windows).
7. **Flags** on a test: `thermal_throttling`, `slowing_down` (second half of the runs more
   than 5% slower), `app_cold_only` (OS file cache could not be purged), `quick_mode`.
8. **Status, never zero:** `ok`, `invalid`, `skipped`, `incompatible` or `error`, with a reason.

## Known limitations

- **RAM preview** cannot be started or timed by script; `ae.preview` is a stand-in.
- **Viewport** speed is not measured.
- **Cold OS cache:** only on macOS with admin rights (`sudo purge`); otherwise flagged `app_cold_only`.
- **Version differences:** each result records the exact app versions and what the build produced.
  Comparing machines on different versions is flagged by the scoring step (Phase 3).
- **Other creative apps** in the multitasking test are represented by the memory ballast, not opened.
- **Octane** runs at the plugin's default render settings, which may differ between Octane versions; the version is recorded.
- **Intel Macs** cannot run After Effects 27 or later (Adobe, July 2026).
